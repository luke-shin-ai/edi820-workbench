# samples/public/: BAI2 files published by banks, not generated here

Every other file under `samples/` is generated by `scripts/gen-fixtures.mjs`. The two files in this
folder are different on purpose: they are copies of BAI2 files that banks and payment vendors publish
in their own documentation, so the reader can be checked against a file whose bytes it never chose.

Nothing here is a customer file and nothing here was written by this project. Do not add real bank
data to this folder either.

| file | source | copy notes |
|---|---|---|
| `bai2-westpac-npp.txt` | Westpac / Qvalent, "BAI2 NPP sample file", <https://bankrec.support.qvalent.com/docs/downloads/bai2/bai2-npp-sample-file.txt> (downloaded 2026-11-23) | verbatim, including the CRLF line endings the published file uses |
| `bai2-southstate-guide.txt` | SouthState Bank, "BAI-2 Format: Bank Administration Institute Cash Management Balance Reporting Specifications, User Guide", sample file on page 12, <https://prd.ssbcdn.com/ssbweb/media/pdf/ssb-bai2-format-v3-jan-2025-rev.pdf> (downloaded 2026-11-23; guide updated 2025-01-14) | records verbatim; the PDF puts a trailing space after each record's `/`, and this copy ends lines with LF instead of the PDF's layout |

Both publishers present the account numbers, names and references as fictitious examples. They are
reproduced here only so that a reviewer can run the reader over them again:

```bash
npx tsx scripts/verify-public-bai2.mjs
npx vitest run test/unit/public-bai2.test.ts
```

## What the copies prove

`scripts/verify-public-bai2.mjs` parses each file with `src/bai2/reader.ts` and prints what the reader
found. As of 2026-11-23 both files parse with **no issues**: the record counts in the `49`, `98` and
`99` trailers agree with the records read, and the `49` account control totals agree with the amounts
in the `03`, `16` and `88` records.

Getting there needed a correction in the reader, not in the copies. Until 2026-11-22 the reader took
only the first [type code, amount] pair of an `03` record and compared the `49` total against that
pair plus the *signed* detail amounts. Both published files, and the BAI convention they follow, add
the amounts of every `03` group and every `88` continuation as they appear on the wire (a debit is a
positive amount whose direction comes from its type code). With the corrected rule all 27 records of
each file reconcile exactly, and the two files disagree with each other in useful ways: one carries
continuations (`88`) for both summaries and detail text, the other has four accounts in one group.

## Adding a third file

Add the file, its source URL and download date to the table, extend `scripts/verify-public-bai2.mjs`
and `test/unit/public-bai2.test.ts`, and keep the copy byte-identical except for the notes above. A
file that the reader cannot parse is worth keeping too: say what the reader reported and why.
