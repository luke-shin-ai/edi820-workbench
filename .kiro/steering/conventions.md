# Conventions: build discipline for 「820」

## Evidence over claims
- When a feature is finished, append a line to `EVIDENCE.md`: date, task id, command run, result (counts), and the commit-ish. A hook does this on `PostTaskExecution`; if the hook is off, do it by hand.
- A "passing" claim must name the command and the number (`vitest run` -> 41 passed). No unqualified "tests pass".

## Safety around files
- Never write to `samples/` from code paths; samples are fixtures.
- Never delete or rewrite a user's input file. Outputs go to `out/<timestamp>/`.
- `verify` must be read-only: it re-derives and compares; it never mutates.

## Commit style
- `feat(parser): decode SIGN TRAILING OVERPUNCH`
- `fix(reconcile): control total delta sign for negative amounts`
- `spec(820): add requirement for implied decimals`
- One logical change per commit; a PBT regression fix references the failing test file.

## Forbidden
- Floating-point money. Ever.
- Network calls at runtime.
- Adding `/.kiro` (or any of its subfolders) to `.gitignore` - Kiroween submission requires the directory in the repo root.
- Copying text or code from other Kiroween participants' submissions.

## Honesty rules for the write-up
- If a Kiro feature was tried and did not help, say so and say what happened instead (judges score "thoughtful strategy", not enthusiasm).
- Distinguish "generated by Kiro" from "reviewed by Kiro" whenever the difference matters.
